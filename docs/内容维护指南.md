## 二、添加一条资源（最常用）

打开 `data/resources.json`，这是一个数组。**在数组末尾的 `}` 后面加一个英文逗号，然后粘贴新的一段**：

```json
{
  "name": { "zh": "服务名称", "en": "Service Name" },
  "tag": { "zh": "一句话定位", "en": "One-liner" },
  "desc": {
    "zh": "详细介绍，会显示在卡片上半部分。",
    "en": "Detailed description shown on the card."
  },
  "logo": "缩写",
  "url": "https://example.com/",
  "badge": { "zh": "获取方式", "en": "Access" },
  "tags": ["云服务器", "免费额度", "长期有效"],
  "provider": "提供方名称",
  "requirements": "使用要求，会显示在红色那个框里。"
}
```

### 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | 是 | 名称，中英两份 |
| `tag` | 否 | 副标题，卡片标题下方小字 |
| `desc` | 是 | 简介，卡片上的正文 |
| `logo` | 否 | 左上角方块里显示的 1–2 个字符 |
| `url` | 是 | 点「官网入口」跳转的地址 |
| `badge` | 否 | 详情里「获取」那一栏的文案 |
| `tags` | **是** | 标签数组，见下方说明 |
| `provider` | 否 | 来源，显示为 `by 提供方` |
| `requirements` | 否 | 使用要求，红色框 |

## 三、`tags` 标签规则（重要）

`tags` 是一个字符串数组，决定了卡片能出现在哪些筛选结果里。它同时承担三件事：

### 1. 必须有一个状态标签（三选一）

| 状态标签 | 什么时候用 | 页面上的颜色 |
| --- | --- | --- |
| `长期有效` | 长期开放，没有结束时间 | 绿色 |
| `现在可薅` | 活动还在进行，但可能结束 | 橙色 |
| `失效` | 已经结束或服务下线 | 灰色 |

> 每一条**必须有且仅有一个**状态标签。没有的话会被当成「失效」。

### 2. 分类标签决定顶部筛选按钮

当前可用分类（必须与 `data/categories.json` 里的一致）：

```
云服务器    域名/TLS    国内镜像源    API 羊毛    学生/学习资源    Google 服务
```

### 3. 还可以加任意自定义标签

比如 `免费额度`、`限时活动`、`学生认证`、`公益镜像` 等。这些标签会显示在卡片底部，**点一下就能按它筛选**。

**完整示例**：

```json
"tags": ["云服务器", "限时活动", "学生认证", "现在可薅"]
```

这个例子里：`云服务器` 让它出现在云服务器分类下，`现在可薅` 是它唯一的状态标签，`限时活动` 和 `学生认证` 是额外标签。

## 四、其他数据类型

### 工具 `data/tools.json`

```json
{
  "name": "VS Code",
  "icon": "VS",
  "category": "dev",
  "desc": { "zh": "中文说明", "en": "English desc" },
  "tags": { "zh": ["免费", "跨平台"], "en": ["Free", "Cross-platform"] },
  "free": true,
  "url": "https://code.visualstudio.com/"
}
```

`category` 可选值：`dev` / `design` / `productivity` / `system`。注意工具的 `tags` 是**双语对象**（中英各一份），和资源不同。

### 白嫖 `data/baipiao.json`

字段与资源基本相同，额外多一个 `expire`（有效期说明）和 `category`：

```json
"category": "quota"   // 可选：quota / api / event / lottery
"expire": { "zh": "长期有效", "en": "Ongoing" }
```

### 公益站 `data/charity.json`

多一个 `org` 字段（维护方）：

```json
"org": { "zh": "清华大学", "en": "Tsinghua University" }
"category": "mirror"   // 可选：mirror / api / tool
```

### 笔记 `data/posts.json`

```json
{
  "date": "2025-11-02",
  "title": { "zh": "标题", "en": "Title" },
  "excerpt": { "zh": "摘要", "en": "Excerpt" },
  "tags": { "zh": ["部署"], "en": ["Deploy"] },
  "url": "#notes"
}
```

## 五、JSON 编辑三条铁律

JSON 格式很严格，写错了页面会白屏或数据加载失败：

1. **最后一项后面不能有逗号**
   ```
   ❌ { "a": 1, }      ← 多了一个逗号
   ✅ { "a": 1 }
   ```
2. **所有字符串必须用双引号**，不能用单引号
   ```
   ❌ 'name': 'abc'
   ✅ "name": "abc"
   ```
3. **中文引号「」可以，但不能在字符串里直接写英文双引号**，要转义成 `\"`
   ```
   ❌ "desc": "他说"你好""
   ✅ "desc": "他说「你好」"
   ```

### 改完怎么检查有没有写错

**方法一（推荐）**：用 VS Code 打开文件，写错了会立刻出现红色波浪线。

**方法二**：命令行校验

```bash
node -e "JSON.parse(require('fs').readFileSync('data/resources.json','utf8')); console.log('格式正确')"
```

**方法三**：直接刷新页面，按 `F12` 打开控制台，如果数据加载失败会有红色报错。

## 六、本地预览与发布

### 本地预览

因为用了 JSON 文件，**不能直接双击 HTML 打开**（浏览器的 file:// 安全限制），需要起一个本地服务：

```bash
cd D:\KMin-github\KMin.github.io
python -m http.server 8000
# 然后浏览器打开 http://localhost:8000/
```

### 发布到线上

```bash
git add .
git commit -m "content: 更新资源"
git push
```

推送后 GitHub Pages 会自动重新构建，约 1 分钟生效。如果线上还是旧的，按 `Ctrl + F5` 强制刷新。
