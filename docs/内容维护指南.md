> **文件名就是卡片名字**：一眼能看出 `r-cloudflare-workers.md` 对应 Cloudflare Workers 卡片。
> 文件名与 front-matter 里的 `id` **必须一致**（`r-cloudflare-workers.md` ↔ `id: r-cloudflare-workers`）。

### 命名规则

| 目录 | 文件名规则 | 示例 |
| --- | --- | --- |
| `resources/` | `r-英文名.md` | `r-cloudflare-workers.md` |
| `baipiao/` | `b-英文名.md` | `b-deepseek-new-user-credit.md` |
| `charity/` | `c-英文名.md` | `c-ustc-open-source-mirror.md` |
| `tools/` | `序号-英文名.md` | `014-vercel.md` |
| `posts/` | `序号-日期.md` | `007-2025-06-01.md` |

**规则**：
- 英文名用小写字母和连字符，不要中文、空格、大写
- 详情页地址就是 `detail.html?id=r-cloudflare-workers`，可读性好、方便分享
- 改名时**文件名和 `id` 要一起改**，否则详情页会 404

### 顺序由 order 字段控制

列表显示顺序**不再由文件名决定**，而是由 front-matter 里的 `order` 字段控制：

```yaml
id: r-cloudflare-workers
order: 1                    # ← 数字越小越靠前
name:
  zh: Cloudflare Workers
```

调整顺序只需改 `order` 的值，**不用重命名文件**。

### 命名规则（重要）

| 目录 | 文件名规则 | 示例 | 说明 |
| --- | --- | --- | --- |
| `resources/` | `r-XXX.md` | `r-028.md` | 序号递增，**不复用** |
| `baipiao/` | `b-XXX.md` | `b-011.md` | 同上 |
| `charity/` | `c-XXX.md` | `c-009.md` | 同上 |
| `tools/` | `序号-英文名.md` | `014-vercel.md` | 序号决定显示顺序 |
| `posts/` | `序号-日期.md` | `007-2025-06-01.md` | 序号决定显示顺序 |

> **为什么要有序号**：列表按文件名排序。`r-009` 排在 `r-010` 前面，但 `r-10` 会排在 `r-9` 前面（字符串排序），所以一律用三位数补零。

## 二、内容与骨架的分离机制

```
content/*.md          data/*.json          页面 HTML
（你写的）     构建→   （自动生成）  读取→  （自动渲染）
```

| 层 | 位置 | 你需要改吗 |
| --- | --- | --- |
| 内容层 | `content/` 64 个 `.md` | ✅ **改这里** |
| 数据层 | `data/` 5 个 `.json` | ❌ 构建自动生成，别手改 |
| 骨架层 | `*.html` + `assets/` | ❌ 开发负责 |

### 哪些 data/*.json 是手改的

不是所有 JSON 都由 Markdown 生成，这 3 个是配置，需要直接手改：

| 文件 | 用途 |
| --- | --- |
| `data/categories.json` | 定义筛选按钮（分类 id 与显示名） |
| `data/site.json` | 首页统计数字、最近更新日期 |
| `data/about.json` | 关于页的时间线与技能标签 |

### 3.2 tags 标签规则

`tags` 决定卡片出现在哪些筛选里，**只写分类标签和自定义标签**。

> ⚠️ **状态标签已废弃**：`长期有效` / `现在可薅` / `失效` 三个旧标签不再写进 `tags`，
> 卡片上的时效标签改由 `validFrom` / `validTo` 两个日期字段自动生成，见 [3.2.1](#321-时效标签规则)。

**分类标签（决定顶部筛选按钮，可选一个）**：

| 分类标签 | 对应 id | 当前数量 |
| --- | --- | --- |
| `云服务器` | `server` | 7 |
| `域名/TLS` | `domain` | 3 |
| `国内镜像源` | `mirror` | 5 |
| `API 羊毛` | `api` | 5 |
| `学生/学习资源` | `learn` | 3 |
| `Google 服务` | `google` | 4 |

**自定义标签（可选任意个）**：如 `免费额度`、`限时活动`、`学生认证`、`公益镜像`。点一下就按它筛选。

```yaml
tags:
  - 云服务器        # ← 分类标签
  - 限时活动        # ← 自定义标签
  - 学生认证        # ← 自定义标签
```

### 3.2.1 时效标签规则

卡片右上角的时效标签**不手写**，由两个日期字段决定（写在 front-matter 里）：

```yaml
validFrom: "2026-11-08"    # 开始日期，可省略
validTo: "2026-11-10"      # 结束日期，可省略
```

四种组合对应四种展示：

| 写法 | 卡片显示 | 说明 |
| --- | --- | --- |
| 两个都不写 | `长期有效` | 无明确开始和结束时间且至今有效 |
| 只写 `validFrom` | `2026.11.8 -- ∞` | 仅已知开始时间 |
| 只写 `validTo` | `2026.11.10结束` | 仅已知结束时间 |
| 两个都写 | `2026.11.8 -- 2026.11.10` | 完整区间 |

**结束日期已过**的条目：卡片整体变浅灰、降饱和，并在底部标签行追加一枚
不可点击的「活动已结束」标签。

> 日期格式随意（`2026-11-8` / `2026/11/08` / `2026.11.8` 都行），
> 构建时会统一成 `YYYY.M.D`（不补零），与卡片显示一致。

### 3.3 detail 详情字段

对应详情页黄框里的五行：

| 字段 | 显示为 | 什么时候用 |
| --- | --- | --- |
| `quota` | 「额度」 | 能领多少（领取类资源） |
| `usage` | 「用途」 | 用来做什么（镜像源/工具类，**替代 quota**） |
| `limit` | 「限制」 | 有什么门槛 |
| `avoid` | 「避坑」 | 容易踩的坑 |
| `valid` | 「有效期」 | 什么时候失效 |
| `scope` | 「核实范围」 | 信息来自哪里、何时核实 |

> `quota` 和 `usage` **二选一**：有 `usage` 时优先显示「用途」。镜像源这类没有「额度」概念的用 `usage`。

### 3.4 教程段落

写在 front-matter 的 `---` 之后：

```markdown
## 教程

### 第一步标题

这一步的具体说明。

### 第二步标题

这一步的具体说明。
```

| 情况 | 写法 | 详情页表现 |
| --- | --- | --- |
| 有教程 | 写 `## 教程` + 若干 `### 步骤` | 显示教程区 |
| 无教程 | **完全不写** `## 教程` | 教程区自动隐藏 |

> 镜像源、下载源这类没有「领取」动作的条目，**不要写教程**。

## 四、统一卡片数据接口（资源 / 白嫖 / 公益站）

三类条目现在**共用一套数据结构和一套卡片组件**，这是本次改造的核心：

```
content/{resources,baipiao,charity}/*.md
        ↓ build-content.js（buildEntry 统一构建）
data/*.json  每条都是同一个结构：id / group / name / tag / desc / logo / url /
             badge / tags / category / detail / guide
             + 可选槽位 provider·requirements（资源）/ expire（白嫖）/ org（公益站）
        ↓ main.js（buildEntryCard + renderEntryGrid）
三个页面的卡片视觉与交互完全一致
```

**卡片上有哪些东西**：

| 位置 | 内容 | 数据来源 |
| --- | --- | --- |
| 左上台标 | logo 字母 | `logo` |
| 标题 / 副标题 | 名称 + 一句话定位 | `name` / `tag` |
| 右上时效徽章 | 长期有效 / 日期区间 | `validFrom` / `validTo` 两个日期字段 |
| 右上首选标签 | 分类标签（可点击筛选） | `tags[0]` |
| 正文 | 简介 | `desc` |
| 附加信息行 | 资源=使用要求（红框）/ 白嫖=有效期 / 公益站=维护方 | `requirements` / `expire` / `org` |
| 官网直达 | 蓝色按钮，显示域名 | `url` |
| 底部标签行 | 其余标签，逐个可点击筛选 | `tags` |
| 右下 | 获取方式 + 详情按钮 | `badge` / `id` |

**要加新标签**：只改对应的 `.md`，在 `tags:` 里加一行，卡片底部立刻多一枚可点击的标签。

**要改卡片布局**：只改 `main.js` 里的 `buildEntryCard`，三个页面同时生效。

## 五、白嫖功能区

**对应页面**：`baipiao.html` + `detail.html?id=b-XXX`

**要改的文件**：`content/baipiao/` 下的 `.md`

### 与资源区的差异

白嫖的字段 = 资源的字段 + 一个额外字段：

```yaml
categories:                      # ← 独有：所属分类（数组，可多个）
  - api
```

> 旧的 `expire` 字段（自由文本「长期有效」「每月刷新」）已废弃，
> 时效统一改用 `validFrom` / `validTo`，规则见 [3.2.1](#321-时效标签规则)。

**`categories` 可选值**（数组，一篇可同时属于多个分类）：

| 值 | 显示名 | 当前数量 |
| --- | --- | --- |
| `server` | VPS/服务器 | 4 |
| `api` | 免费 API | 6 |
| `student` | 学生权益 | 1 |

写法：

```yaml
categories:            # 单分类
  - server

categories:            # 多分类（同时出现在两个筛选里）
  - server
  - api
```

> 也兼容旧的单值写法 `category: api`，构建时会自动包成数组。
> 分类数量加起来大于总条数，是因为有 3 条同时属于两个分类。

## 八、详情页信息怎么改

详情页 `detail.html?id=xxx` 的内容全部来自卡片对应 `.md` 文件的 **`detail:` 段和 `## 教程` 段**。

### 详情页各区域来源

| 详情页区域 | 数据来源 | 改哪里 |
| --- | --- | --- |
| 面包屑「首页 / 资源 / 标题」 | `name.zh` | front-matter |
| 大标题 | `name` | front-matter |
| 时效徽章 | `validFrom` / `validTo` | front-matter |
| 分类文字 | `tags` 里第一个标签 | front-matter |
| 简介 | `desc` | front-matter |
| 标签行 | `tags` | front-matter |
| **「额度」/「用途」行** | `detail.quota` 或 `detail.usage` | front-matter |
| **「限制」行** | `detail.limit` | front-matter |
| **「避坑」行** | `detail.avoid` | front-matter |
| **「有效期」行** | `detail.valid` | front-matter |
| **「核实范围」行** | `detail.scope` | front-matter |
| **教程区** | `## 教程` + `### 步骤` | 正文 |
| 「访问官网」按钮 | `url` | front-matter |
| 「返回列表」按钮 | 自动（按分类回对应页） | 不用改 |

### 只想改详情页，不动卡片

卡片上显示的是 `name`、`desc`、`requirements`、`tags`；
详情页黄框显示的是 `detail.*`。两者独立，**改 `detail` 不会影响卡片**。

## 九、增删改操作速查

### ➕ 新增一张资源卡片

1. 新建 `content/resources/r-你的英文名.md`（如 `r-vercel-edge-functions.md`）
2. 复制现有文件作模板，改 `id`（与文件名一致）、`order`、`name`、`url`、`tags` 等
3. 运行 `node build-content.js`
4. 刷新 `resources.html` 确认

### ➕ 新增一张白嫖卡片

1. 新建 `content/baipiao/b-你的英文名.md`
2. 记得填 `expire` 和 `category`，`id` 与文件名一致
3. 运行 `node build-content.js`

### ➕ 新增一张公益站卡片

1. 新建 `content/charity/c-你的英文名.md`
2. 记得填 `org` 和 `category`，`id` 与文件名一致
3. 运行 `node build-content.js`

### ✏️ 修改卡片文字

| 想改 | 改哪个字段（front-matter 内） |
| --- | --- |
| 标题 | `name.zh` / `name.en` |
| 副标题 | `tag.zh` |
| 正文简介 | `desc.zh` |
| 左上角字母 | `logo` |
| 跳转地址 | `url` |
| 右下角标签 | `badge.zh` |
| 来源（by xxx） | `provider` |
| 红框使用要求 | `requirements` |
| 状态（绿/灰） | `validFrom` / `validTo` 日期 |
| 所属分类 | `tags` 里的分类标签 |

### ❌ 删除一张卡片

1. 删除对应的 `.md` 文件（如 `content/resources/r-deepseek-platform.md`）
2. 运行 `node build-content.js`
3. 详情页链接 `detail.html?id=r-deepseek-platform` 会显示「没有找到这个条目」

> 删除后**不要复用这个 id**，否则旧分享链接会指向新内容。

### 🔀 调整卡片顺序

资源、白嫖、公益站的顺序由 front-matter 里的 **`order` 字段**控制：

```yaml
order: 5      # 数字越小越靠前
```

改一个数字就能调整位置，**不需要重命名文件**。

工具和笔记仍按文件名前序号排序（`001-` 排最前）。

## 十一、YAML 常见错误

front-matter 是 YAML 格式，比 JSON 宽松但仍要守规则。

### 错误 1：冒号后面必须有空格

```yaml
❌ url:https://example.com/
✅ url: https://example.com/
```

### 错误 2：文本含冒号要加引号

```yaml
❌ desc: 说明: 这是例子
✅ desc: "说明: 这是例子"
```

### 错误 3：文本以特殊符号开头要加引号

```yaml
❌ desc: #标签开头
✅ desc: "#标签开头"

❌ badge: *重要
✅ badge: "*重要"
```

### 错误 4：缩进必须用空格，不能用 Tab

```yaml
❌ name:
→→zh: 名称        （→ 表示 Tab 键）

✅ name:
    zh: 名称        （4 个空格或 2 个空格）
```

### 错误 5：列表项用 `- ` 开头（横杠后要有空格）

```yaml
❌ tags:
  -云服务器

✅ tags:
  - 云服务器
```

### 错误 6：双语对象必须两层缩进

```yaml
❌ name: zh: 名称
✅ name:
    zh: 名称
```

### 校验办法

```bash
node build-content.js --check
```
有问题的文件会显示 `✗ 文件名  错误信息`。
